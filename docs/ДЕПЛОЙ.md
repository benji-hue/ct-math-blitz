# Запуск «Крока» в Telegram: пошагово

Есть три пути:

- **Путь А — без компьютера, из GitHub, на Cloudflare.** Нужны два токена и
  около 10 минут: всё остальное (база, адрес, секреты, бот) делает workflow.
- **Путь Б — вручную с компьютера** (ниже): для тех, кто хочет видеть каждую команду.
- **Путь В — на свой сервер** (VPS с Linux): тот же код в Docker, HTTPS через
  Caddy, выкладка из GitHub по SSH. Нужны домен и доступ к серверу.

Пути взаимоисключающие: бот ходит туда, куда его переключили последним.

## Путь А. Одной кнопкой из GitHub

### 1. Токен бота

Telegram → [@BotFather](https://t.me/BotFather) → `/mybots` → ваш бот →
**API Token**. Токен — это пароль бота: не публикуйте его и не присылайте в чат.
Если он всё же утёк — там же **Revoke current token** и возьмите новый.

### 2. Токен Cloudflare

1. [dash.cloudflare.com](https://dash.cloudflare.com) — войдите (достаточно бесплатного аккаунта).
2. **My Profile → API Tokens → Create Token** → шаблон **Edit Cloudflare Workers** → *Use template*.
3. В правах добавьте **Account → D1 → Edit** (Workers Scripts: Edit и Account Settings: Read в шаблоне уже есть).
4. *Continue to summary → Create Token*. Токен показывается один раз — скопируйте.

### 3. Секреты в GitHub

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Секрет | Что это |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | токен из шага 2 |
| `BOT_TOKEN` | токен из шага 1 |
| `CLOUDFLARE_ACCOUNT_ID` | необязательно: нужен, только если в Cloudflare несколько аккаунтов |
| `GEMINI_API_KEY` | необязательно, но желательно: ключ Google AI Studio — Gemini 3.5 Flash-Lite становится основной моделью (текст, фото, задания), Qwen на Workers AI — запасной. Без ключа отвечает только Qwen |
| `OPENAI_API_KEY` | необязательно: ключ любого OpenAI-совместимого API (Groq, Cerebras, DeepSeek, OpenRouter…); адрес и модель — `OPENAI_BASE_URL` и `OPENAI_MODEL` в `worker/wrangler.jsonc` |

### 4. Запуск

**Actions → Deploy to Cloudflare → Run workflow.** Через 3–5 минут в сводке
запуска появятся ссылка на мини-апп, ссылка на бота и таблица проверок.
Что делает workflow:

1. создаёт базу D1 и адрес `https://krok.<поддомен>.workers.dev` (если их ещё нет);
2. применяет миграции, собирает и публикует мини-апп с воркером (ИИ, API, бот, напоминания);
3. кладёт секреты воркера; секрет вебхука выводится из токена бота;
4. ставит вебхук, кнопку меню «Открыть Крок», команды и описание бота;
5. проверяет живым запросом: приложение открывается, подпись Telegram принимается,
   ИИ отвечает, вебхук принимает только Telegram.

Повторный запуск безопасен — так выкатываются обновления. Галочка
*allow_anonymous* пускает к ИИ из обычного браузера (показ с ноутбука; лимиты для
анонимов строже) — после защиты запустите без неё.

Галочка *eval* после деплоя прогоняет **пробный вариант**: ученик решает задания с
семью ошибками разных типов, ИИ их разбирает; плюс проверка решения по фото,
сократический режим, безопасность, белорусский язык, генерация заданий. В поле
*eval_models* можно перечислить модели для сравнения (`@cf/…` — Workers AI,
`gemini:…`, `openai:…`). Полный вариант получает первая модель, остальные —
сокращённый набор: бесплатный лимит Workers AI общий с учениками. Отчёт — в сводке
запуска; итоги прогона — в [ПРОБНЫЙ-ВАРИАНТ.md](ПРОБНЫЙ-ВАРИАНТ.md).

Галочка *e2e* проходит путь ученика в настоящем браузере: мини-апп открывается
«как из Telegram», ИИ отвечает на вопрос, проверяет фото решения и разбирает
ошибку из тренировки; скриншоты — в артефакте *e2e* и в логе.

### 5. По желанию

BotFather → ваш бот → **Bot Settings → Configure Mini App** → тот же адрес: тогда
приложение откроется и кнопкой в профиле бота (а не только кнопкой меню).

### Если запуск упал

Причина написана в красной аннотации запуска.

| Сообщение | Что сделать |
| --- | --- |
| Нет секрета … | добавьте секрет с таким именем (шаг 3) |
| Cloudflare не принял токен / не хватает прав | пересоздайте токен по шагу 2, проверьте право D1 → Edit |
| У токена несколько аккаунтов | задайте секрет `CLOUDFLARE_ACCOUNT_ID` одним из перечисленных значений |
| Telegram отклонил токен | токен бота скопирован не полностью или отозван — возьмите новый в BotFather |
| ⚠️ ИИ не отвечает | приложение работает и с заготовленными ответами; проверьте Workers AI в панели Cloudflare |

## Путь Б. Вручную с компьютера

Понадобится: Node.js 22 и бесплатный аккаунт Cloudflare.

### 1. Бот

[@BotFather](https://t.me/BotFather) → `/newbot` → имя и username. Сохраните **токен**.

### 2. Cloudflare

```bash
npm install                 # зависимости мини-аппа
npm run worker:install      # зависимости воркера
cd worker
npx wrangler login          # откроется браузер, войдите в Cloudflare
npx wrangler d1 create krok # создаст базу и выведет database_id
```

Вставьте `database_id` в `worker/wrangler.jsonc` и примените схему:

```bash
npm run db:init
```

### 3. Секреты

```bash
npx wrangler secret put BOT_TOKEN        # токен из BotFather
npx wrangler secret put WEBHOOK_SECRET   # любая длинная случайная строка, например: openssl rand -hex 32
```

Необязательно — если есть легальный доступ к внешней модели:

```bash
npx wrangler secret put GEMINI_API_KEY   # Gemini станет основной: AI_PROVIDERS уже "gemini,workers-ai"
# или любой OpenAI-совместимый API (DeepSeek, OpenRouter, Groq…):
npx wrangler secret put OPENAI_API_KEY   # плюс OPENAI_BASE_URL и OPENAI_MODEL в vars
```

Без этих ключей всё работает на Cloudflare Workers AI.

### 4. Деплой

Из корня репозитория:

```bash
npm run worker:deploy
```

Команда соберёт мини-апп и опубликует воркер. В конце будет адрес вида
`https://krok.<ваш-аккаунт>.workers.dev`. Впишите его в `MINI_APP_URL` в
`worker/wrangler.jsonc` и повторите `npm run worker:deploy` — так кнопки бота
будут открывать приложение.

### 5. Настроить бота

```bash
BOT_TOKEN=… WEBHOOK_SECRET=… APP_URL=https://krok.<ваш-аккаунт>.workers.dev npm --prefix worker run bot:setup
```

Скрипт поставит вебхук, кнопку меню «Открыть Крок», команды и описание.

### 6. Проверка

1. Откройте бота → `/start` → «Открыть Крок».
2. Пройдите онбординг, решите пару заданий.
3. Вкладка «ИИ» → задайте вопрос — ответ должен печататься по мере генерации.
4. Напишите боту вопрос текстом — придёт короткий ответ.
5. `https://<адрес>/api/ai/status` покажет подключённые модели.

## Путь В. Свой сервер

Тот же код, что на Cloudflare, работает в обычном Node.js: база — файл SQLite
в томе Docker, Qwen — через API Cloudflare (у Cloudflare остаётся только модель),
HTTPS — Caddy с бесплатным сертификатом Let's Encrypt. Выкладывает workflow
**Deploy to own server**: собирает образ, проверяет его, загружает на сервер по
SSH, перезапускает и переключает бота.

**Что нужно:** VPS с Linux (хватит 1 ГБ памяти), домен и SSH-доступ.

### 1. Домен

Запись **A** домена (или поддомена, например `krok.example.by`) → IP сервера.
Своего домена нет — подойдёт бесплатный поддомен, например на
[duckdns.org](https://www.duckdns.org). Telegram открывает мини-апп только по
HTTPS, а сертификат выдаётся на домен.

### 2. Порты

На сервере и в панели хостинга открыты **80 и 443**. Если они свободны, HTTPS
даёт Caddy из `deploy/compose.yml`. Если на сервере уже работает **nginx** с
другими сайтами, деплой его не трогает, а добавляет ему отдельный файл сайта
для вашего домена (`deploy/nginx-site.sh`) и получает сертификат через certbot;
каждое изменение проверяется `nginx -t`, при ошибке файл убирается. С другим
веб-сервером (apache и т. п.) деплой остановится и покажет, кто занял порты.

### 3. Вход на сервер

**Проще — по паролю root.** Если пароль хоть раз попадал в чат или письмо,
сначала смените его на сервере (`passwd`) и дальше используйте только новый.
В GitHub пароль хранится зашифрованным и в лог не попадает, а за деплой
вводится один раз: остальные команды идут по тому же соединению.

**Надёжнее — по ключу.** На своём компьютере:

```bash
ssh-keygen -t ed25519 -f krok_deploy -N ""      # пара ключей только для деплоя
ssh-copy-id -i krok_deploy.pub root@IP_СЕРВЕРА   # открытый ключ — на сервер
```

SSH не на 22-м порту — добавьте `-p ПОРТ` к `ssh-copy-id`.
Docker на сервере ставить не нужно: если его нет и вход под root, workflow
поставит его сам (официальный скрипт get.docker.com). Под другим пользователем —
поставьте Docker сами и добавьте пользователя в группу `docker`.

### 4. Секреты и переменная в GitHub

**Settings → Secrets and variables → Actions → Secrets:**

| Секрет | Что это |
| --- | --- |
| `SERVER_HOST` | IP сервера |
| `SERVER_USER` | пользователь SSH, обычно `root` |
| `SERVER_PASSWORD` | пароль этого пользователя — **или** вместо него `SERVER_SSH_KEY`: содержимое файла `krok_deploy` (закрытый ключ). Только сюда, не в чат |
| `SERVER_KNOWN_HOSTS` | по желанию, но лучше задать: ключ сервера, чтобы GitHub не отправил секреты на чужую машину. Без него первый деплой примет ключ сервера на веру и напечатает строку `ssh-ed25519 …` — её и добавьте сюда. Или возьмите заранее: `cat /etc/ssh/ssh_host_ed25519_key.pub` на сервере |
| `SERVER_PORT` | по желанию, если SSH не на 22-м порту |
| `BOT_TOKEN`, `GEMINI_API_KEY` | те же, что для Cloudflare |
| `CLOUDFLARE_AI_TOKEN` | по желанию, для запасной модели Qwen: Cloudflare → API Tokens → Create Custom Token → **Account → Workers AI → Read** |

ID аккаунта Cloudflare для Qwen workflow найдёт сам по `CLOUDFLARE_API_TOKEN`
(или задайте секрет `CLOUDFLARE_ACCOUNT_ID`).

**Вкладка Variables:** `KROK_DOMAIN` — домен из шага 1, без `https://` (можно и
секретом). Без неё используется `krok-ct.duckdns.org` — адрес этого проекта.

### 5. Запуск

**Actions → Deploy to own server → Run workflow.** Галочка *switch_bot*
(включена) переключает бота на сервер и выключает напоминания у старого
воркера на Cloudflare, чтобы они не приходили дважды. Прогресс учеников не
теряется — он хранится в облаке Telegram; настройки напоминаний восстановятся,
когда ученик откроет приложение.

Без секретов сервера workflow только собирает и проверяет образ — так можно
убедиться, что всё собирается, ещё до настройки сервера.

**Вернуться на Cloudflare** — запустить *Deploy to Cloudflare*: бот переключится
обратно, расписание воркера восстановится.

**Вручную на сервере:** `cd ~/krok && docker compose logs -f` — журнал,
`docker compose restart` — перезапуск. База лежит в томе Docker `krok_data`.

## Версия на GitHub Pages (PWA)

Workflow `pages.yml` публикует приложение на GitHub Pages при пуше в `main`.
Чтобы там работал ИИ, задайте переменную репозитория `KROK_API_BASE` (адрес
воркера или своего сервера); адрес Pages уже разрешён в `ALLOWED_ORIGINS`. Вне Telegram
запросы к ИИ без подписи отклоняются, пока не включён `ALLOW_ANONYMOUS`.

## Локальная разработка

```bash
npm run dev                      # только интерфейс, http://localhost:5173
cd worker && cp .dev.vars.example .dev.vars
npm run db:init:local && npm run dev   # воркер с заглушкой ИИ, http://localhost:8787
```

## Чек-лист перед защитой

- [ ] Профиль → «Демо-профиль для показа»: заполненная статистика, серия,
      прогноз. Ваш настоящий прогресс вернётся при выходе из демо.
- [ ] Проверьте ИИ на площадке. Если сеть плохая, в демо-режиме приложение
      покажет заранее заготовленные ответы (они помечены «демо»).
- [ ] Показ с ноутбука в браузере: запустите Deploy to Cloudflare (или Deploy to
      own server) с галочкой *allow_anonymous* (лимиты для анонимов строже),
      после защиты — без неё.
- [ ] Заряженный телефон, запасной хотспот, видео-запись демо на крайний случай.
